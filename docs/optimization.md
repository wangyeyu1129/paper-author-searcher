# 性能与内存优化：测量与决策记录

每项改动都在真实保存的数据上做了新旧代码对比，结果一致后才提交。没有采用的方案也记录在这里，说明原因，方便日后复核。

## 没有采用（及原因）

- **E4 按“姓 + 名首字母”分桶**：姓名比较最后一步是模糊匹配，会接受分桶会分开的组合（例如姓氏差一个字母），分组结果会悄悄改变。改用了数学上不会误判的上界检查。
- **E5 并查集（Union-Find）**：单链接会把彼此并非都重复的记录串成一组，改变去重决定。保留完全链接，只去掉重复计算。
- **F3 把存档拆成 JSONL 流式读取**：最大的真实存档（1,007 篇）整体加载只需 0.8 s、128 MB；改格式要同时改 6 处读取方（续跑、评估、基准、复核、诊断、迁移），收益不抵成本。存档超过几百 MB 时再考虑。

## 复现方法

- 对比新旧代码：`git worktree add <dir> <旧提交>`，分别用 `PYTHONPATH=<dir>/src` 和 `PYTHONPATH=src` 运行同一命令，比较输出与耗时。
- 离线重放：基准配置中 `run.http_cache_mode` 设为 `replay`，只读录制的响应，不产生 API 费用。
