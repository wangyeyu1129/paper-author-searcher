## 问题与修改

Semantic Scholar 原 100 篇运行的 54 个查询错误中，52 个为 HTTP 429、2 个为 HTTP 404；另 38 篇因缺少支持的标识符而未查询。主要问题是匿名请求限流和检索入口不足，不能把这些结果解释为不存在 PDF。本轮加入官方批量请求、节奏控制、来源冷却、缓存、异常响应回退与受现有身份规则约束的标题查询；保存结构化错误分类、实际逻辑请求数和冷却跳过数。

新增 Crossref 已登记全文/落地页解析，补齐 Unpaywall 联系邮箱配置及所有 OA 落地页传递，识别原始位置中的 arXiv ID，并增强作者公开目录、机构仓储和出版页面的引用元数据与结构化链接解析。旧 HTTP 学术链接可尝试同一路径 HTTPS；非 OA 标记本身不作为链接可访问性的结论，仍必须观察实际公开 PDF 响应及可靠论文身份绑定。页面探测复用 DNS 固定连接安全检查。

新增离线比较工具，以相同论文范围、未变更的元数据和归属决定为前提，分别统计 URL、实际有效文件和内容确认，记录新增与丢失的有效 PDF 论文。它不会请求 API 或读取人工参考清单中的 PDF URL。

教授 Resolver、Ownership Validator、身份匹配和 PDF 内容验证阈值未修改。标题线索、HTML 响应、Crossref 登记链接和机构域名都不能单独计为成功；证据不足的候选仍未经确认。

## 测试与限制

Python 3.8.0 下完整 418 项单元测试通过，`git diff --check` 通过。新增覆盖批量分组/缓存、429 与长 Retry-After、超时恢复、404、接口异常和 HTML 中间页冷却、邮箱脱敏与必需配置、Crossref 冲突、缺 DOI 作者匹配、仓储/作者页/结构化元数据、跨来源继续检索、相同范围比较、缺文件和内容待确认。对比 CLI 用已有基线进行离线自对比，得到 URL 25/100、内容确认 21/100 且差值为零；这只是工具校验，不是修改后真实复测。

真实 API 的可用性、Unpaywall 合法联系配置、匿名 Semantic Scholar 配额，以及 PDF 当前公开性需要新实测确认。公开页面解析受响应预览与后续链接上限约束；不做搜索引擎爬取、验证码处理或访问限制绕过。原始数据缺少作者/年份/DOI 时不补造证据。未设置邮箱前不会使用虚构联系地址试跑。

安全设置及复测/比较命令见 [docs/pdf_discovery.md](../../docs/pdf_discovery.md)。用户终端变量不能自动传回已有 Codex 进程，可在配置邮箱的同一终端直接执行这些命令，再用生成的报告进行离线对比。
