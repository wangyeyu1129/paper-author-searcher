49 份有效文件包含 1 份 Poster；44 份内容确认文件中有 9 份文档类型 unknown，不能算作已确认全文。新的 `search_sufficiently_satisfied` 单独记录验证全文已获得，不替代来源完整率，不会使 7% 变高。

**下降主要来自冷却。** 完整率始终要求处理范围内所有配置来源的查询状态均完整；`ok`、`not_found`、`not_applicable` 属于完整，`partial`、`error`、`disabled` 属于不完整。原 13 篇中 4 篇保持完整、9 篇变为不完整；另 3 篇变为完整，得到 7 篇。全部 9 篇退化的唯一记录原因都是冷却跳过：8 篇 Public Pages、1 篇 Semantic Scholar。最新 93 篇不完整中，47 篇仅有 deferred 未完成查询（已查询的正常 metadata 404 不算运行故障）。被跳过的查询没有执行，不能假定补做就一定成功。

**诊断观察不等于 HTTP 失败。** Public Resources 的 201 条旧事件中，97 条为实际逻辑调用的终止失败，104 条为重定向过程中阻止访问冷却目标；后者不属于新的目标 HTTP 429。204 次 cooldown skips 包含请求前与重定向后的阻止。119 次 cache hits 的成功/失败细分没有旧日志，不能还原；新代码已分别记录。最新 Public Resources 有 6 个终止于 429 的逻辑失败，Semantic Scholar 有 7 个；HTTP 内部重试的响应次数没有旧追踪，不能将上述数量当作全部 HTTP 传输失败次数。`Source Temporarily Deferred 19 → 92` 是受影响论文数；来源级 deferred 警告共有 237 条，可重复。查询预算不足另有 2 条页面读取上限、2 条后续链接上限观察。

**CiteSeerX/Internet Archive 的重复成本。** 保存的错误明确显示 CiteSeerX 请求跳至 `web.archive.org`。Public Resources 记录 Archive 5 个终止 429、101 条重定向 deferred。原实现只缓存成功响应和单 URL 的确定失败，冷却中断的重定向关系没有缓存，所以仍反复请求入口，再在 Archive 前被阻止；这还把 deferred 混进了失败事件。

本轮修复：

- 有期限地记住实际观察到的重定向关系；已知目标仍冷却时直接保留 incomplete，不再请求入口。
- 公开页面回退查询中，多个不同 URL 持续导向同一个冷却来源时应用临时来源背压；多目标网关不按单一来源处理，冷却到期后正常恢复。规则通用，没有 CiteSeerX/Archive 域名特判，不绕过限流，也不把未查询的 URL 判为不存在。
- 拆分实际终止请求失败、缓存成功/失败、请求前/重定向冷却跳过和预算不足；HTTP 层另记录含重试的操作尝试与错误响应。HTTP 尝试仍可能包含重定向跳数，报告明确注明范围。
- 修复后续链接预算：按整篇论文共享的实际子页面网络查询计数；缓存命中和请求前冷却跳过不消耗网络预算。所有未完成查询仍标记不完整。
- Resolver 与离线比较共用完整率定义；manifest、工作流报告和比较结果增加独立的搜索目标满足状态，要求 verified 归属、文件完整性、格式、内容和 full_text/preprint 类型。unknown 明确保留未确定。

Python 3.8 下全部 **481 项测试通过**，新增 18 项覆盖重定向缓存到期、重复路由背压、多目标网关、缓存错误与真实失败区分、共享预算、内部重试计数及满意度/完整率独立性。未改身份、归属或内容验证阈值，未新增 PDF Provider。上述优化后的网络请求减少量尚未实测，本轮不重跑 100 篇。

最新报告记录 timeout=10 秒、retries=1；旧报告缺失这些配置，不能证明实验网络条件完全相同。指标是检索范围覆盖和自动判定，不是人工 Ground Truth 的 Precision/Recall。
