# 召回率修复：逐项离线验证（2026-10-19）

依据召回率诊断报告中的修复清单，按推荐顺序逐项实现。每项都在 `calibrated-with_hints-20261018` 上用 `paper-benchmark run --replay-from` 离线重放后再做下一项。

离线重放的含义：
- 元数据请求只从 HTTP 缓存读取，其他网络请求一律拒绝；
- 锚点使用原 run 保存下来的结果；
- 整个过程 API 花费为 0。

当前代码的基线重放（`replay-0-baseline`）与原 run 相比，32 人中 30 人完全一致，其余 2 人各差 1 篇。

## 联网验证（`live-20261019-recall-fixes`）

## 精度保护：常见中文名，按作者档案碎片生效（`f165843`）

把四项召回修复放在旧真值上模拟时，精度从 97.1% 降到 92.0%。所以精度保护和召回修复一起上线。

保护只在同时满足两个条件时生效：
- 名字是常见中文名（常见姓氏表放在包内数据文件里）；
- 该作者 ID 没有被 ORCID 锚定。

其他人沿用原规则。所有阈值都在 `PrecisionGuardConfig`（`Settings.precision`）里。

1. **碎片画像**：统计每个作者 ID 碎片的院系出现次数，与本人院系比对。本人院系取请求的院系，加上本人锚点论文上的院系。证据足够但吻合度太低的碎片判为外来，碎片里的论文只能靠论文级 ORCID 逐篇认领。
2. **院系级机构核对**：机构规则还要求论文署名的院系吻合。署名里没写院系的视为中性。
3. **机构矛盾不升级**：论文机构既不是当前机构，也不在本人论文出现过的机构里，就不允许靠合作者或跨数据源证据升级。
4. **合作者**：撞名风险高的名字（常见姓加短名，如 "Hui Li"）不计入，除非出现在本人自己的论文里。主页列出的全部论文都可以作为合作者种子（`listed_works`），不受锚点预算限制。
5. **本人论文的来源**：锚点现在记录自己来自哪篇论文（`AnchorEvidence.work`）。本人论文上看不到院系时，院系检查保持中性，避免误伤换过单位的人。

|---|---:|---:|---:|---:|---|
| 不开保护 `replay-6-guard-off` | 84.3% | 83.3% | 98.2% | 97.0% | 42/55 |

## 与诊断预测不同的地方

- **修复 2 需要额外处理一个问题。** OpenAlex 按 Wei Wang 的 ORCID 查询时，返回了一个自身记录着另一个 ORCID 的同名档案 A5100391888，导致整组被判为"ORCID 冲突"。现在，记录自身的 ORCID 与提供的 ORCID 不一致时，就不再把它当作锚定记录。
- **修复 4 需要加一道保护。** Wei Lu 带 ORCID 的 OpenAlex 档案混入了多位同名者，挂了 89 个机构，曾使 17 篇明显不是他的论文（印染、纳米孔 DNA、核辐射成像）被判为已确认。现在机构历史超过 `maximum_history_institutions`（12）的身份不提供历史机构证据。加上这道保护后，Wei Lu 没有新增误检，Lu Lu 新增的 6 篇未标注论文都是他本人的。
- **修复 5 暴露了一条真值重复。** Kevin Ellis 真值里同一论文的 ICML 版和 arXiv 版是两条记录，已合并为一条。
